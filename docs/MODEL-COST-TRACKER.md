# Workspace model cost tracker

The broker records provider usage across Pi, Codex, Claude Code and Copilot requests that use the workspace model gateway. It aggregates by authenticated workspace owner across that owner's workspaces. The editor's **Model Costs** status item and command show Today, This week, This month and Year to date. Operations contains the same period cards. Periods use UTC calendar boundaries; weeks begin Monday.

Provider `usage.cost` is the source of truth when present. Cached reads, cache writes and output counters are retained separately; cost already includes provider cache pricing, so no token rate is applied again. Missing cost remains unknown and contributes to the unpriced-request count. An incomplete stream is not counted as free. Native protocol responses without cost can be reconciled through the fixed OpenRouter generation endpoint, with at most three delayed lookups per request. Incomplete all-zero generation metadata is not accepted as a completed cost record.

The ledger is private SQLite under local state. It contains request identifiers, owner, timestamp, model, protocol, generation identifier and numeric usage, never prompts, generated text or API keys. Duplicate delivery of the same broker request ID does not double count it. The read API authenticates the user; the editor uses its existing short-lived workspace capability, and the broker resolves its owner. The extension only contacts the local broker. It receives no upstream credential and needs no extra egress.

Tracking starts at installation. These are observed workspace totals, not an account-wide invoice: direct external calls, earlier traffic, and ordinary app-chat calls outside the workspace gateway are not included. Pi and Copilot both use chat completions and are intentionally aggregated rather than guessed from their protocol. The tracker does not impose a spending cap or change the separate Azure-only test ceiling.

Historical account analytics requires an OpenRouter management key, which is different from the existing inference credential. No management key is exposed to workspaces or requested for this implementation. A future server-side importer could use it to backfill history, but must reconcile overlapping request data rather than add account totals to the workspace ledger.

References: [OpenRouter usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting), [generation metadata](https://openrouter.ai/docs/api/api-reference/generations/get-generation), [analytics access](https://openrouter.ai/docs/cookbook/administration/analytics-cost-control). [Ori's official harness announcement](https://openrouter.ai/blog/announcements/ori-harness/) describes provider configuration and lists a usage toolbar as future work; this tracker works at our common broker boundary and does not depend on an undocumented Ori telemetry API.
