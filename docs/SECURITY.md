# Security boundaries

The configured pilot uses tenant-bound Microsoft Entra sign-in, validated ID tokens and revocable server-side sessions. History, projects, workstations, previews and editor profiles are scoped to tenant/object identity. Operations and infrastructure mutations require the configured operator identity. Loopback binding, strict HttpOnly cookies, CSRF checks and owner checks protect control-plane routes. This remains one local broker, not a public or distributed production deployment. A clean installation without Entra configuration retains explicit local-owner mode; the configured pilot does not fall back if authentication fails. See [Identity](IDENTITY.md).

Azure Sandboxes are isolated execution environments. Generated commands run as an unprivileged sandbox user with bounded time/output, restricted environment and no-new-privileges controls. The operator's Azure and OpenRouter credentials remain local. Root bootstrap commands are fixed trusted source; workspace content cannot supply them.

Quick Python has denied network egress and no model access. Headless inference executes in the local broker; headless code receives no model capability. GUI Pi/Ori, Codex and Claude use a signed, expiring, workspace-scoped model capability through the reverse service relay. GUI code can reuse its own capability: this is a deliberate developer trust boundary, not proof that only an approved harness makes calls.

Outbound sandbox networking defaults to deny. The authenticated relay exposes fixed app/IDE ports and curated package/model services. It accepts neither arbitrary host forwarding nor credentials for another workspace. The package gateway permits approved registry GET requests, enforces the five-day release-age policy and uses narrowly scoped, human-approved age exceptions. Failed installs do not relax policy.

Generated-app previews have isolated origins (separate ports) and restrictive content policy. An app retains its own origin so its subresource requests can authenticate; the browser same-origin boundary isolates it from the trusted app. Artifacts and approval documents retain opaque sandbox origins. Preview scripts cannot read the HttpOnly sign-in cookie. Mutation requests and websockets require the preview’s own Origin; top navigation and external connections remain denied. Preview forwarding strips browser credentials and remote Set-Cookie headers. IDE previews use a stable, separate origin per workstation and allow their own webviews/service worker. Folder trust remains an explicit user choice. Opening arbitrary parent folders is not required.

Source sync excludes credential paths, dependencies, symlinks and oversized data. This is filename-based filtering, not full DLP. Blob checkpoints are private and broker-owned; Azure credentials never enter the guest. Headless and GUI state remain separate with conflict-aware source transfer.

Tool availability is not permission to send email or mutate enterprise systems. The tool service must enforce human authorization and bind approval to the exact action. Project and workstation deletion preserve their established confirmation flows. Stop compute preserves disk and history.

Keep local state, credentials, generated work and conversation data out of source publication. A reviewed manifest and exact-index privacy audit are required before committing. A public push requires explicit user approval.

Compute replacement uses a private, bounded archive of the same user’s home, including native tool history and credentials. This transfer is distinct from source-only project synchronization. The original cloud home remains stopped for recovery, and the local archive has private permissions. Extraction runs as the sandbox user with the data archive filter. External symlinks and special files are excluded. Saved editor profiles transfer only reviewed preference/layout fields; they do not transfer model credentials, workspace trust or conversation state.
